Non-training attribute control: gravity, camera, brightness, quality

In progress · source-pair sanity clips only so far, no steered/verdict results yet · no training, no LoRA anywhere

A pivot from the case-by-case steering vectors on the earlier page, which each extracted a direction as teacher-minus-base on one specific clip -- tangled up with that clip's own content. Here the direction is built from prompt-contrastive pairs across multiple different scenes, on base H3 alone (zero LoRA, zero trained checkpoints, construction included), then averaged into a single generic direction meant to transfer to a held-out scene regardless of its own content.

Method: for each of 3 source scenes (duck-falls-in-box, potato-in-water, domino-in-juice), run base H3 twice with the identical seed and reference image, changing only the prompt along one attribute axis (e.g. "falls continuously under gravity" vs. "stays suspended, never falls"). Hook every transformer block in both runs, record each block's real output (mean over packed-sequence rows) at 7 representative denoising steps, diff the two runs, and average over all steps and all 3 scenes into one direction per block. Apply that direction to blocks L30–L49 (the span established in the earlier page's causal test) on a fresh base H3, generating a 4th, held-out scene from its own neutral prompt -- no attribute language added -- to see whether the direction can push the output even though nothing in the prompt asked for it.
Status: the jobs building these 4 directions (gravity, camera motion, brightness, visual quality) are still running. What's below are the source-pair sanity clips completed so far -- i.e. the two contrastive generations each direction is being built from, uploaded as they land. No steered/held-out result, no verdict, for any attribute yet. This page will be updated once each direction is built and the held-out test is checked with dense frame sampling and quantitative pixel-level tracking, per the correction on the earlier page.
